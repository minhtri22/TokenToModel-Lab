## B01 V4: answer hypotheses, proof semantics, and F07
### A. Answer hypothesis is the true unit
For any candidate answer `h=(record_entity_id, accession_id, receipt_or_decision_event_id, location_id, effective_time_or_interval, authority_rule_version)`. Two cards may refer to the same record yet assert DIFFERENT locations/times; therefore `|entities|=1` is insufficient. `SELECT` iff exactly ONE **nondefeated fully evidenced answer hypothesis** remains, AND precisely ONE designated target card represents the hypothesis under the precommitted one-key scorer.
**Private, schema-level distinctions:** `entity_equivalence_class` groups same record+version; `answer_hypothesis_id` distinguishes event/location/time, even for same record. `target_card_key` identifies the exact canonical answer-record card; `proof_card_keys` are necessary evidence cards and need not equal target card. Never choose the canonical key by hash, index or arbitrary public order.
A proof consists of a finite set of cards whose typed claims jointly entail all precommitted mandatory premises under policy P; a **minimal sufficient proof set** has no proper sufficient subset. A hypothesis may have multiple alternative sufficient sets, each encoded in `minimal_sufficient_proof_sets`. Independent reviewer MUST reconstruct the supported hypotheses and sets from records, not rely on generator gold. Explicit `defeater` handling is required for superior authority or later effective-time contradiction. A circular support chain, contradictory equally authoritative sources, or two candidate keys for the same answer is INVALID FIXTURE, not silently resolved.
**Set computation**: evaluate typed predicates `IDENTITY`, `SCOPE`, `EVENT`, `LOCATION`, `TIME_VALID`, `AUTHORIZED`, `NOT_DEFEATED`. Build `H_supported` from consistent minimal proof sets and policy P. The cardinality is over hypotheses, not distinct entities or gold keys.
`ABSTAIN` if no uniquely supported hypothesis. Diagnostic reason priority is `UNRESOLVED_AUTHORITY` > `MULTIPLE_SUPPORTED_HYPOTHESES` > `MISSING_PREMISE` > `NO_SUPPORTED_HYPOTHESIS`, with `all_applicable_reasons` separately retained; never infer reason from marker words. If there is a verified explicit *negative* answer, a yes/no question could answer “No”, but this protocol is **not yes/no**: it requests a verified record/location; when none qualifies, the action is ABSTAIN. Owner must approve this scoring definition.
For a SELECT fixture, `answer_key_set` MUST contain one target-card key. If multiple cards genuinely correspond to one eligible answer key, fixture is invalid for the one-key version. A successor could redefine multi-key scoring and key null but cannot mix it into R8-D without new owner approval.

### B. F07 abstract truth-conditional witness — NOT R8 data
**Rephrased SELECT task**: “Which verified receipt record, if any, establishes the effective arrival location of accession X? Return its card key; otherwise ABSTAIN.” It never asks yes/no.
**Precommitted synthetic-domain policy P-REC-V1 (proposed, NOT legal-world assertion)**: A receipt event is established only when (i) accession identity and effective interval match, (ii) either an authorized contemporaneous acknowledgement **or** a subsequent independently authorized audit reconciliation is linked to that exact accession/event, and (iii) no superior timely contradicting source defeats it. An audit reconciliation involving the wrong accession is not evidence. A dispatch forecast is not sufficient. This is a research toy-domain policy only; owner must affirm its validity for the chosen synthetic world.

|---|---|---|
| Twin A: authorized audit ledger A has link `audit_id->accession_X`; non-authoritative copy B links to Y; target card says X@L1; forecast exists | X's receipt/location substantiated by authoritative edge and policy P | SELECT target X@L1 |
