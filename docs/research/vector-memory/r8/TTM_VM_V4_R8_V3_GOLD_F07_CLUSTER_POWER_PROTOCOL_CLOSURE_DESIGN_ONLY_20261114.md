## B01 — Gold ontology and fixed deterministic validation
Define `candidate_entity_id` (private stable record identity), distinct from `card.key`. Two cards describe the **same target** iff they refer to the same record/entity *and effective version*, not merely same object, label, location or similar text. Evidence adjudicator must construct equivalence classes before computing action.
For target entity e, define minimal sufficient proof sets `M_e={S_1,...,S_k}`: each S_j subset of card IDs, jointly entails every mandatory premise (identity, scope, event, effective time, authorized source); no proper subset entails all. Evidence card and target card may differ. Negated or contradictory premises must be processed under a frozen authority and effective-time ordering, not by string status.
`supported(e)` iff at least one valid proof set and no unresolved defeating proof. Let `E={e:supported(e)}`.
- `SELECT` iff |E|=1 and the unique e has a **single designated answer-key card** (one-key scorer contract); `target_card_id` is that card and proof sets may include others.
- `ABSTAIN` iff |E|=0, |E|>=2, or authority conflicts make set indeterminate. Any ambiguity of which card key represents the same answer record means **invalid fixture HOLD**, not arbitrary reduction to one key.
- If redundant keys for same record are unavoidable, alternative scorer must accept explicit answer-key equivalence set and target-key chance null becomes `|accepted_keys|/32`; that is a **different scorer/version**. R8 one-key candidate requires exactly one accepted key for every SELECT. Never use canonical hashing of public keys to artificially choose gold.
**Exclusive ABSTAIN reason ordering** (diagnostic only): `UNRESOLVED_AUTHORITY` if conflicting valid authorities cannot be ordered; else `MULTIPLE_SUPPORTED_TARGETS` if >=2 distinct tied supported entities; else `MISSING_PREMISE` if a specifically required fact for an otherwise uniquely identified candidate is absent; else `NO_SUPPORTED_TARGET`. This ordering avoids multiple assigned reason labels but must not turn semantically different failures into falsely unique proof. Evidence review records `all_applicable_reasons` as well as `primary_abstain_reason`.
**Private schema V3 required fields:** `candidate_entities`, `target_card_id|null`, `accepted_answer_keys` (must length 1 for SELECT), `proof_sets_by_entity` with `minimal_card_key_sets`, `mandatory_premises`, `proof_defeaters`, `authority_precedence`, `temporal_precedence`, `primary_abstain_reason`, `all_applicable_reasons`, `pair_id`, `event_graph_component`, `template_cluster`, `relation_family`, `fold_id`, `truth_conditional_edge_edit`. Public schema allowlist only question and 32 opaque card keys/text/source IDs.
Validator MUST: enumerate distinct entities, normalize equivalence, verify minimality of each proof set, enforce authorized authority/time precedence, certify exactly one target key for SELECT and none for ABSTAIN; reject circular support, two unranked authoritative sources, and unsupported gold. Independent content reviewer must rederive E from visible 32 cards, not private gold alone.

### F07 feasibility — abstract proof table, not R8 data
Assume a *predeclared domain policy* P: physical receipt of accession X is established by contemporaneous receiver acknowledgment **OR** a subsequent independent inventory reconciliation signed by authorized audit officer and linked unambiguously to X. A dispatch queue alone is insufficient. P must be part of the frozen authority model, not chosen after reading the case.
| Abstract condition | Same question: "Was accession X physically received, and where?" | Proof | Outcome |
|---|---|---|---|
| A: shipping forecast exists but neither qualifying receipt nor signed authorized reconciliation | identity + forecast; essential physical receipt evidence absent | No sufficient proof | ABSTAIN / MISSING_PREMISE |
| B: forecast as above, plus audit reconciliation tied to X, confirming accepted arrival and location L under policy P | identity + policy P + independent audit reconciliation + temporal validity | Single entity/effective record proven, answer key L | SELECT |
This is an **abstract model feasibility witness**, not a generated case and not an empirical confirmation that a lexical oracle can be prevented. The truth-changing feature is the authorized evidence relation and corroboration, **not** token `signed`. Other SELECT and ABSTAIN cases must contain signatures and reconciliations used in different roles; the reviewer must verify the existence of an F07 matched pair without mere presence/absence marker. If policy P is invalid in owner domain or cannot be encoded, **B01 remains HOLD**.

## B03 — Graph connected components, folds, A/B allocation
Candidate target: 8 semantic relation families x 4 pairs = 32 pairs / 64 cases, 32 cards/case. This balanced table is **not proof of 32 independent units**.
Before G3, construct an undirected **leakage graph** with nodes = cases. Add an edge for shared `pair_id` or shared effective `event_graph_id`, reused `template_cluster_id`, or shared source text/fingerprint above frozen similarity threshold. Compute connected components (union-find). All nodes of a component MUST share one fold and cannot cross a model training/evaluation boundary. No after-the-fact splitting or duplicate republishing to inflate components.
**Predeclared fold algorithm:** canonical-sort component SHA IDs; apply HMAC-SHA256 keyed by sealed G2 allocation key to component ID; sort by digest, then assign whole components greedy to the least case-count among 4 folds with stable fold-index tie break. Keys/digests stay private. Output a private fold manifest and public **aggregate** counts. If <4 components, no four-fold CV; HOLD_DESCRIPTIVE_ONLY. This minimum of four is solely feasibility for 4 folds, **not adequacy of statistical independence or power**. Even if >=4, no inferential independence claim absent event/template audit.
Primary diagnostic is group-held-out by template-connected components; leave-family-out secondary, explicitly estimating cross-family transfer and potentially impossible if family connects all cases. If components are too big for meaningful holdout, record `CV_NOT_IDENTIFIABLE`, no resplitting.
**Blind twins:** allocate one twin per pair to Rater A and the other to Rater B, with per-rater 16 SELECT + 16 ABSTAIN, using a private precommitted balanced allocation. Randomize delivery order, mask paired IDs, prevent accessible cross-session comparison and withhold opposite twin. **Consequence:** A and B do not independently score the SAME 64 cases; interrater agreement on the full 64 is not estimable. If the original scientific protocol requires two independent full-64 raters, it is mathematically incompatible with the twin non-exposure rule under only two raters. No silent claim of interrater reliability. Owner must choose this disjoint design or adopt a new blinded routing protocol with extra raters; until decision G0/G1 HOLD.
Do not release pair allocations until A/B scores and receipts frozen. No unblinding until all protocol-controlled score packets SHA-pinned.

## B04 — Fixed restricted shortcut adversaries (parameter register; DESIGN PROPOSAL)
All feature extraction uses only allowed public fields; no training on test labels, no gold/stratum/family/pair IDs. Design uses Python 3.12, scikit-learn version EXACT frozen at G2, solver/hyperparams committed and read back before G3. If installed versions differ from this proposed register, revise protocol prospectively **before candidate**; cannot silently substitute.

| Oracle | Features / transform | Frozen estimator/parameters | Evaluation |
|---|---|---|---|
| O1 Order | row position decile, card position extrema | majority table from TRAIN folds only, tie->ABSTAIN | held-out component |
| O2 Metadata | ID/source lengths; char classes; text and key lengths (bucket 5), card order | LogisticRegression(C=1, solver=liblinear, max_iter=1000, random_state=20261114) | held-out component |

| O4 Question | TfidfVectorizer(analyzer=word, ngram_range=(1,2), min_df=1, max_features=2000, sublinear_tf=False); question-only AND question+O2 | logistic config as O2 | held-out component |
| O5 Key selector | per-card marker/length/status/authority features | LogisticRegression as O2, trained only on TRAIN candidate cards with group weighting; select max posterior; tie->first card by public order *solely for tie resolution* | held-out SELECT, 1/32 uniform null |
| O6 Combined | concatenation of O2+O3+O4 plus per-card aggregate tokens | logistic config as O2 | held-out component |

**Frozen feature-space rules:** Unicode NFKC; lowercase; word token pattern `(?u)\b\w+\b`; missing metadata encoded as missing not guessed; class imbalance use unweighted empirical data; no selecting best n-gram, folds or sign after viewing outcome; fixed random state 20261114 for CV and permutations. Search budget = exactly these 8 families, no autotuning or extra model sweeps. Training data from entire connected component never split. A model that cannot fit due to one class in TRAIN => `NOT_ESTIMABLE/HOLD`, not PASS.
**Hard FAIL:** a fixed oracle gives perfect held-out action (64/64) OR perfect SELECT gold keys (32/32), with integrity/provenance verified; a deterministic access leak can be FAIL even if folds unavailable. Other high predictions screened by B05. Unusually low accuracy is treated two-sided, not reversed post hoc for a falsely favorable headline.
For SELECT key null: under one accepted key per 32 cards, uniform chance 1/32. Action null for balanced random label prediction 1/2. Joint null depends on explicit strategy and MUST NOT be assigned 1/64 by default.

## B05 — Power, sample size and permitted inference
**Primary prospective choice:** `EXPLORATORY_DESCRIPTIVE_ONLY` with N=32 pairs, possible effective N<32. No confirmatory claims that R8 excludes shortcuts. Statistical tests may flag suspicious leakage, but failure to reject is **HOLD_INCONCLUSIVE** for absence claims. No numerical "PASS anti-shortcut" threshold will be inferred from R8's own output.
**Illustrative, not power of R8:** under optimistic i.i.d. Bernoulli null p=.5, Holm worst-case alpha=.0125 two-sided, a moderate true shortcut accuracy .625 has low detection power at n=32; with only 8 effective units chance of detecting moderate leakage is much worse. Dependence from twins/template lowers effective N. Do not use n=64 as iid.
**Power specification for any later confirmatory successor (not R8):** effect of concern >= .125 above 0.5 (accuracy 0.625), desired power >= 0.8, familywise alpha .05 across four primary oracle families using Holm; sample size n independent components derived by fixed power simulation/exact-binomial design *before data* with source/repro code and null. If the corpus cannot supply needed number of components, this R8 must remain descriptive. This specification is a design target, not a certification that n=32 achieves it.
**Diagnostic procedure for R8:** preserve pairs/connected components in all model training/validation; report raw action accuracy, balanced accuracy, SELECT key top-1, joint exact match and per-family; provide two-sided exact/permutation p-values **only if exchangeability and component count justify them**, with Holm on O2/O3/O4/O6 and CI computed over independent connected components. A randomization test should flip labels at whole pair level when design supports exchangeability, not randomly shuffle 64 labels. For key-target null, permute card keys within a case only under exchangeability with target location; preserve case component, no invalid iid assumptions.
**Two distinct gate interpretations**:
- `FAIL`: known deterministic oracle or confirmed label/gold/schema/custody flaw, or predeclared shortcut validly significant after Holm.
- `HOLD_INCONCLUSIVE`: incomplete/invalid tests, low N_eff, or no significant leak where sensitivity is insufficient.
- `PASS_SCOPED_DESCRIPTIVE_QA`: structural and semantic checks PASS and all fixed diagnostics have been *executed and reported* without hard FAIL; DOES NOT assert no shortcut or justify scientific release. Statistical nonrejection never upgrades the claim.
No "PASS_SCOPED_DIAGNOSTICS" language implying shortcut absence. In particular G4 may PASS scope for complete descriptive readback while `ANTI_SHORTCUT_ABSENCE=NOT_ESTABLISHED`.
